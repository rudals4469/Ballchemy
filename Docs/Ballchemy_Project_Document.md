# Ballchemy 프로젝트 문서

## 1. 프로젝트 개요

- 엔진: Unity 6.3 LTS `6000.3.18f1`
- 장르: 2D 로그라이크 벽돌깨기
- 기본 스크립트 경로: `Assets/_Project/Script`
- 외부 영구 성장 없음
- 한 판은 약 5~6스테이지
- 시작 공은 2~3개
- 최종 보스에서는 공 100개 이상 발사를 목표로 한다.

Ballchemy는 고정된 블록 전투와 아이작 스타일의 랜덤 맵 탐험을 결합한다.

플레이어는 각 스테이지의 방을 탐험하고, 전투를 클리어해 공과 재화를 늘리며, 상점·보상방·이벤트방을 활용해 빌드를 완성한 뒤 보스를 처치한다.

---

## 2. 핵심 게임 루프

```text
런 시작
→ 스테이지 맵 생성
→ 방 탐험
→ 전투방 클리어
→ 보상 획득
→ 빌드 성장
→ 보스 처치
→ 다음 스테이지
→ 최종 보스
```

플레이어는 모든 방을 반드시 방문할 필요가 없다.

더 많은 공과 강한 빌드를 원할수록 추가 탐험의 위험을 감수하게 만드는 구조를 목표로 한다.

---

## 3. 스테이지 구조

각 스테이지는 정사각형 방이 상하좌우로 연결된 아이작 스타일의 랜덤 맵으로 생성한다.

### 필수 보장 방

- 시작방 1개
- 보스방 1개
- 상점방 1개
- 보상방 1개
- 이벤트방 1개
- 일반 전투방
- 네임드 전투방

모든 방은 시작방에서 도달 가능해야 한다.

후반 스테이지일수록 전체 방 수가 증가한다.

### 임시 권장 방 수

| 스테이지 | 전체 방 수 |
|---|---:|
| 1 | 8~10 |
| 2 | 9~11 |
| 3 | 10~12 |
| 4 | 11~14 |
| 5 | 13~16 |
| 6 | 15~18 |

전체 방 수에는 시작방과 특수방이 모두 포함된다.

수치는 데이터로 분리하고 플레이 테스트 후 조정한다.

---

## 4. 지도 공개 규칙

처음부터 위치가 공개되는 방:

- 시작방
- 보스방
- 상점방
- 보상방
- 이벤트방

일반 전투방과 네임드 전투방은 처음에는 숨긴다.

플레이어가 방을 방문하거나 인접 지역을 탐험하면 지도 정보가 확장된다.

보스방의 위치는 항상 알 수 있지만, 도달 경로는 직접 탐험해야 한다.

---

## 5. 방 상태와 이동

### 기본 상태

```text
Unvisited
→ InCombat
→ Cleared
```

### 클리어한 방

- 전투가 다시 발생하지 않는다.
- 보상을 다시 받을 수 없다.
- 열쇠를 다시 획득할 수 없다.
- 빈 방으로 남는다.
- 이동 경로로 재입장하거나 통과할 수 있다.

### 방 이동

- 방 이동 비용은 없다.
- 클리어한 방 사이의 이동은 무료다.
- 전투 중에는 일반 이동이 잠긴다.

---

## 6. 전투 후퇴

전투 중 후퇴는 체력을 대가로 허용한다.

### 초기 규칙

- 최대 체력의 10%를 지불한다.
- 비용은 소수점 올림이다.
- 후퇴 후 최소 1 HP가 남아야 한다.
- 직전에 있던 방으로 돌아간다.
- 후퇴한 방은 미클리어 상태로 유지된다.
- 해당 방의 블록과 적 상태는 최초 입장 상태로 초기화된다.
- 보상과 열쇠는 획득하지 못한다.

후퇴 비용은 데이터로 분리하고 플레이 테스트 후 조정한다.

보스방 후퇴 허용 여부도 초기에는 허용한 뒤 테스트를 통해 확정한다.

---

## 7. 방 종류

### 시작방

- 스테이지 시작 위치
- 전투 없음
- 최초 이동 거점

### 일반 전투방

- 랜덤 블록 배치
- 필수 적 블록 전멸 시 클리어
- 재화 지급
- 1단계 보상 지급
- 스테이지 열쇠가 숨겨질 수 있음

### 네임드 전투방

- 일반방보다 강한 적과 높은 난이도
- 랜덤 블록 배치
- 더 많은 재화
- 2단계 보상 지급

### 상점방

- 처음부터 지도에 공개
- 열쇠 불필요
- 회복, 최대 체력, 공 구매, 업그레이드, 새로고침 제공
- 스테이지당 한 상점 구조를 기본으로 한다.

### 보상방

- 처음부터 지도에 공개
- 무료 보상 1개 제공
- 전투 없음
- 스테이지당 1회 이용

### 이벤트방

- 처음부터 지도에 공개
- 스테이지 열쇠가 있어야 입장 가능
- 열쇠는 최초 입장 시 소비
- 위험과 보상을 교환하는 선택 제공
- 선택 완료 후 빈 방으로 전환
- 스테이지당 1회 이용

### 보스방

- 처음부터 지도에 공개
- 도달하면 도전 가능
- 클리어 시 3단계 보상 제공
- 다음 스테이지로 이동하면 남은 방은 소멸

---

## 8. 스테이지 열쇠

스테이지 생성 시 일반 전투방 하나를 무작위로 열쇠 방으로 지정한다.

### 규칙

- 플레이어는 열쇠가 숨겨진 방을 미리 알 수 없다.
- 해당 일반방을 클리어하면 열쇠를 획득한다.
- 이벤트방 최초 입장 시 소비한다.
- 다음 스테이지로 가져갈 수 없다.
- 보스를 처치하고 다음 스테이지로 이동하면 미사용 열쇠는 사라진다.

### 열쇠 방 후보

포함:

- 일반 전투방

제외:

- 시작방
- 네임드 전투방
- 상점방
- 보상방
- 이벤트방
- 보스방

---

## 9. 방 전투 규칙

기존 웨이브 하강 구조를 제거하고 고정형 방 전투로 전환한다.

### 확정 규칙

- 블록은 전투 중 아래로 내려오지 않는다.
- 방 입장 시 한 번의 블록 배치를 생성한다.
- 일반방과 네임드방은 초기에는 랜덤 배치를 사용한다.
- 생존 적은 3턴마다 플레이어를 공격한다.
- 필수 적 블록이 모두 파괴되면 방을 클리어한다.
- 방 클리어 전에는 일반 이동이 잠긴다.
- 전투 중 공의 개수는 증가하지 않는다.
- 공 증가는 방 클리어 보상 처리 후 다음 방부터 적용한다.

### 블록 분류

- `RequiredEnemy`: 모두 파괴해야 방 클리어
- `Optional`: 파괴 여부가 방 클리어에 영향을 주지 않음
- `Ignore`: 장식 또는 진행 판정 제외 대상

초기에는 일반 적, 네임드, 보스를 `RequiredEnemy`로 처리한다.

---

## 10. 랜덤 블록 배치

일반방과 네임드방은 초기 구현에서 랜덤 배치를 사용한다.

### 최소 보장 조건

- 블록 간 겹침 없음
- 보드 경계를 벗어나지 않음
- 발사 지점 주변 안전 영역 유지
- 필수 적이 최소 1개 이상 존재
- 방 난이도에 맞는 블록 수와 체력 범위 사용
- 네임드방은 일반방보다 높은 위협도 사용

웨이브 하강이 제거되므로 블록을 보드의 비교적 낮은 영역까지 배치할 수 있다.

블록의 높이, 밀도, 체력, 공격 기능, 보호 구조를 난이도 조절 축으로 사용한다.

추후에는 공이 더 자주 튕기고 블록 지대에 오래 머무르도록 배치 알고리즘을 개선한다.

방 진행 시스템과 배치 알고리즘은 분리한다.

---

## 11. 방 입장 블록 연출

기존 보스 패턴 등장 효과를 일반 전투방의 블록 배치 연출에도 재사용한다.

단, 보스 전용 상태 처리와 시각 연출은 분리한다.

### 권장 흐름

```text
방 입장
→ 입력 잠금
→ 블록 생성
→ 블록 등장 연출
→ 필수 적 강조
→ 연출 완료
→ 플레이어 조준 허용
```

### 연출 중 제한

- 조준 및 발사 금지
- 적 공격 주기 정지
- 방 클리어 판정 정지
- 필요 시 블록 충돌 비활성화
- 연출 완료 후 전투 활성화

### 권장 책임 분리

```text
RoomEncounterController
- 방 전투 시작과 종료 조율
- 방 데이터 전달
- 전투 상태 관리

BlockLayoutPresenter
- 블록 생성 결과 표시
- 등장 순서와 애니메이션 제어
- 연출 완료 이벤트 전달

BossEncounterController
- 보스 전용 규칙
- 보스 음악과 상태 전환
- 공용 블록 등장 연출 호출
```

## 12. 체력 규칙

- 플레이어 HP는 런 전체에서 유지된다.
- 방 클리어 시 자동으로 완전 회복하지 않는다.
- 회복은 주로 상점, 보상, 이벤트에서 얻는다.
- 후퇴에도 HP가 사용된다.

이 구조는 탐험 경로와 위험 관리에 의미를 부여한다.

## 13. 공 성장과 보상

전투 도중 공 추가 블록을 파괴해 즉시 공이 늘어나는 구조는 제거한다.

기존 `AddBallRewardEffect` 계열은 참조 관계를 확인한 뒤 단계적으로 비활성화하고 제거한다.

### 1단계 보상 — 일반방

주요 목적은 공 개수 증가다.

예시:

- 공 +2~4개
- 낮은 확률로 무작위 1성 공
- 재화

### 2단계 보상 — 네임드방

예시:

- 공 +8~12개
- 무작위 또는 지정 2성 공
- 여러 1성 공을 2성 공으로 변환
- 다수 공 보상

### 3단계 보상 — 보스방

단순한 공 추가보다 게임 규칙을 변화시키는 효과를 제공한다.

예시:

- 이후 보상 수량 +1
- 이후 보상 2배 확률
- 보유 공 복제
- 동시 발사 규칙 변경
- 저등급 공 변환
- 특정 공 계열 강화

### 성장 목표

- 시작 공: 2~3개
- 최종 보스: 100개 이상 발사 가능
- 일반방 탐험이 공 수 증가의 주된 수단
- 네임드와 보스 보상은 빌드의 질과 규칙을 변화시킴

## 14. 상점과 이벤트 예시

### 상점

- 현재 체력 회복
- 최대 체력 증가
- 공 구매
- 공 업그레이드
- 상품 새로고침

### 이벤트

- 현재 HP 감소 → 다수 공 획득
- 최대 HP 감소 → 2성 공 획득
- 보유 공 희생 → 3성 공 획득
- 작은 무료 보상
- 아무것도 하지 않고 떠나기

## 15. 구현 로드맵

한 번에 모든 시스템을 변경하지 않는다.

각 단계는 독립적으로 플레이 가능한 상태에서 검증한 뒤 다음 단계로 넘어간다.

### 1단계 — 고정형 방 전투

- [ ] 웨이브 종료 후 블록 하강 제거
- [ ] 한 전투에서 블록 배치를 한 번만 생성
- [ ] 필수 적 전멸 시 방 클리어
- [ ] 방 입장 연출 중 입력 잠금
- [ ] 기존 보스 등장 연출의 시각 부분 공용화
- [ ] 공 추가 블록을 생성 후보에서 제외

### 2단계 — 방 상태와 후퇴

- [ ] `Unvisited / InCombat / Cleared` 상태 구현
- [ ] 클리어 방 재전투 방지
- [ ] 클리어 방 통과 허용
- [ ] 전투 중 후퇴
- [ ] 후퇴 비용 적용
- [ ] 미클리어 방 재입장 시 전투 초기화

### 3단계 — 랜덤 스테이지 맵

## 18. 코드 수정 원칙

- 코드를 추측해서 수정하지 않는다.
- 연결된 GitHub 저장소의 현재 브랜치와 최신 스크립트를 먼저 확인한다.
- 수정 대상 클래스를 참조하는 다른 스크립트도 함께 검색한다.
- 컴파일 오류가 생기지 않도록 공개 API 변경 영향을 확인한다.
- 부분 코드가 아니라 복사해서 교체할 수 있는 전체 스크립트를 제공한다.
- 새 스크립트를 추가할 때 권장 저장 경로를 함께 안내한다.
- 기본 경로는 `Assets/_Project/Script`다.
- 한 스크립트에 책임을 과도하게 몰지 않는다.
- 데이터, 상태, 실행 조율, 표시 책임을 가능한 한 분리한다.
- 한 번에 전체 시스템을 수정하지 않는다.
- 각 구현 단계마다 Unity 컴파일과 플레이 테스트를 확인한다.
- 기존 기능 제거는 즉시 삭제보다 생성 차단 → 참조 제거 → 최종 삭제 순서로 진행한다.
